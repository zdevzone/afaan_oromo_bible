# Third-party resources

The initial Button, Input, Textarea, Select and Dialog wrappers adapt the public Radix-based [shadcn/ui source](https://github.com/shadcn-ui/ui). Copyright (c) 2023 shadcn. Its MIT notice is bundled into the offline About view from [src/assets/licenses/shadcn-ui-MIT.txt](src/assets/licenses/shadcn-ui-MIT.txt).

The paid Shadcnblocks Pro catalog is the project's primary UI resource. Its public catalog, [service terms](https://www.shadcnblocks.com/terms) and [paid license agreement](https://www.shadcnblocks.com/license) were consulted. No purchased component source was available in this workspace, and none is claimed to be included. The component inventory in [docs/UI_UX_GUIDELINES.md](docs/UI_UX_GUIDELINES.md) records this gap for the next design pass.

All reading text currently included is explicitly synthetic test material, not a Bible translation. No publisher's Scripture corpus, local font files, commentary or AI output is distributed in this development scaffold.

The book icons in `src-tauri/icons/` are original geometric development placeholders created for this project, with no third-party artwork. Production branding and icon assets remain subject to owner review before release.

Dependency notices must be completed from the actual JavaScript and Rust lockfiles before distribution; this initial file is not a complete release notice inventory. An ignored worksheet at `.tooling/license-file-audit.json` currently lists 52 production JavaScript package versions and 468 Cargo package versions from the lockfiles, with names, versions, declared license expressions and SHA-256 hashes of top-level license/notice files. It includes Rust packages for all resolved targets, including build and development dependencies. Thirty-nine package versions have no top-level notice file in their installed package directory: one JavaScript package (`react-remove-scroll-bar` 2.3.8) and 38 Rust packages. This does not prove their licenses are missing; release review must find the applicable texts, identify the actual shipped components and verify complete obligations. Recreate the worksheet with `vp exec pnpm licenses list --json --prod > .tooling/js-production-licenses.json`, `cargo metadata --manifest-path src-tauri/Cargo.toml --locked --format-version 1 > .tooling/cargo-metadata.json`, then `node tools/release/combine-license-inventory.mjs .tooling/js-production-licenses.json .tooling/cargo-metadata.json .tooling/license-file-audit.json` using a new output path if the worksheet exists. Application source licensing remains an owner decision. No license for the application's own source is implied by the dependencies' licenses.

The ignored `.tooling/license-target-scope.json` narrows the Rust review input to each proposed native target's Cargo **normal** dependency graph: Linux x64 281 package versions/4 without top-level notice files; Windows x64 232/6; macOS arm64 234/13; macOS x64 234/13. Generate each `.tooling/cargo-tree-<target>.txt` with `cargo tree --manifest-path src-tauri/Cargo.toml --locked --target <target> --edges normal --prefix none --format '{p}'`, then pass each as `--tree <target>=<path>` to `python3 tools/release/scope_license_inventory.py --inventory .tooling/license-file-audit.json --out .tooling/license-target-scope.json`. These graphs still include compile-time procedural macros and do not establish which code or notices are in a final binary; build dependencies and bundle payloads need separate review.

The ignored `.tooling/license-missing-upstreams.json` groups the 19 distinct target-scoped packages without local top-level notice files into six repository URLs from Cargo metadata. Regenerate it with `python3 tools/release/group-missing-notices.py --metadata .tooling/cargo-metadata.json --scope .tooling/license-target-scope.json --out .tooling/license-missing-upstreams.json`, choosing a new output path if needed. Repository URLs and declared SPDX expressions are lookup clues; exact version-matched license text and applicability still require review before a release notice can be marked complete.
